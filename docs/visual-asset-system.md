# Muiz Dev Solutions Visual Asset System

Copy alone will not make the site feel premium.
The website needs a full visual system:

- Copy
- Layout
- Illustrations
- Real screenshots
- UI mockups
- Motion
- Icons
- Photos
- Proof

Do not use random free illustrations just to fill space.
Every asset needs a job.

## Visual Asset Groups

Use six groups:

- Brand illustrations
- Website/project screenshots
- UI mockups
- Motion animations
- Blog images
- Trust/proof visuals

## 1. Brand Illustrations

Illustrations should explain services visually.

Needed illustration topics:

- Website Development
- Business Email Setup
- Domain & Hosting Setup
- SEO Optimization
- Website Maintenance
- Custom Web Applications
- Contact / Project request

Potential sources:

- unDraw
- Storyset
- ManyPixels
- DrawKit
- GetIllustrations
- Blush
- LottieFiles for animated versions

Rule:

Pick one main illustration style and stick to it.

Do not mix random sources with different character styles, line weights, colors, and proportions.

Preferred direction:

- Main style: flat vector or custom UI mockup
- Colors: recolored to match the brand
- Line weight: consistent
- People style: consistent, if people are used
- Background shapes: consistent and minimal

## 2. Project Screenshots

Screenshots prove real work.

For each project, collect:

- Desktop screenshot
- Mobile screenshot
- One important section screenshot

Projects:

- GP Smith AccounTax Services
- HBSI Nigeria
- McBen Leo Cares
- LoveView Estates

Do not place raw screenshots without treatment.

Better presentation:

- Browser frames
- Phone frames
- Carefully angled cards
- Soft background shape behind screenshots
- Short labels such as Business website, NGO website, Real estate

Use screenshots in:

- Home recent projects
- Projects page
- Individual case studies
- About page proof strip, if useful

Do not overload the hero with screenshots unless the composition truly needs it.

## 3. UI Mockups

Mockups explain services.
Screenshots prove work.

Useful mockups:

- Browser mockup showing a website layout
- Business email setup card
- Domain/hosting checklist card
- Website maintenance dashboard card
- Contact-form inquiry card

Service visual plan:

- Website Development: browser + mobile mockup
- Business Email Setup: email inbox or email card
- Domain & Hosting: DNS/SSL checklist
- SEO Optimization: search result preview
- Website Maintenance: status dashboard
- Custom Web Applications: dashboard/admin panel

Example checklist visual:

- Domain connected
- SSL active
- Email records configured
- Website live

This is more custom than generic “person at laptop” art.

## 4. Motion Animations

Motion must not be random.

Use three types:

- Functional motion
- Brand motion
- Illustration motion

Functional motion:

- FAQ opens smoothly
- Service cards reveal by importance
- Contact form success state
- Project screenshots slide into view
- Navbar changes on scroll

Use `motion` or `@formkit/auto-animate`.

Brand motion:

- Hero text reveal
- Logo underscore/cursor blink
- Project mockup reveal
- Line drawing around service cards
- Website screenshot mask reveal

Use `gsap` for memorable moments.

Illustration motion:

- Contact success animation
- Loading state
- Email-sending animation
- Domain connection animation
- Website launch animation

Use `lottie-react`, but only when the animation is custom or carefully selected.

## 5. Blog Images

Do not use random office stock photos for every blog post.

Preferred blog visual style:

- Dark or cream branded card background
- Large article title
- Small abstract illustration or UI mini-card
- Muiz accent color
- Category label

Example:

Blog post: Why Your Business Needs a Website

Visual:

- Browser window
- WhatsApp/contact icon
- Business card shape
- Category label

Recommended approach:

- Custom blog cover graphics
- Simple illustrations
- UI cards
- Abstract website mockups

Use stock photos sparingly.

Possible photo sources:

- Unsplash
- Pexels
- Pixabay
- Kaboompics
- Burst by Shopify

Always check license and avoid trademark/model-release problems.

## 6. Trust / Proof Visuals

Proof visuals reduce fear.

Examples:

- Client website screenshots
- Before/after website structure
- Business email example
- Project process diagram
- Client feedback screenshot, with permission
- Domain/SSL/email setup checklist

For Nigerian clients especially, proof must answer:

- Has he done this before?
- Can I contact him easily?
- Does he understand business?
- Will he disappear after payment?

- Email card appears

- Website Development: browser/mobile mockup

## Recommended Visual Direction

Avoid:

- Generic laptop people illustrations
- Blue/purple tech gradients everywhere
- 3D cartoon characters
- AI robot images
- Code brackets
- Circuit graphics
- Random stock office photos

Use instead:

- Custom UI mockups
- Website frames
- Email cards
- Checklist cards
- Domain/SSL status badges
- Project screenshots
- Subtle abstract shapes
- Few selected illustrations
- Real proof visuals

Visual style name:

Practical Digital Systems

Visual language:

- Dark/cream background
- Sharp accent color
- Clean website mockups
- Business email cards
- Domain/SSL status badges
- Project proof screenshots
- Minimal illustrations
- Controlled motion

## Asset Source Rules

Before using an external asset:

- Check the current license.
- Prefer sources with clear commercial-use terms.
- Save the source URL and license note.
- Avoid mixing too many illustration styles.
- Avoid common overused assets.
- Ask permission before using client feedback screenshots.

Best approach:

Use real screenshots for proof, custom UI mockups for services, and only one or two illustration styles for decoration.
